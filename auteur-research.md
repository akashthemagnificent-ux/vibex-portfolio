# Auteur Repository Research Notes

Source inspected: <https://github.com/agiwhitelist/auteur> (accessed 2026-08-16).

Auteur describes itself as a website-direction skill rather than a component library. Its working method is to lock art direction before implementation, plan a page as a film with a structured commitment sheet, source or generate assets deliberately, build a singular visual system, and then verify the finished result with anti-slop, motion, and system-consistency checks.

The repository presents reusable guidance in `SKILL.md`, `DESIGN.md`, `reference/`, `templates/`, and `scripts/`. Its documented checks include a visual anti-slop linter, motion quality review, contrast/system auditing, and image capture. It warns against default AI patterns, uncontrolled component variety, visual drift, and unmeasured motion.

For Vibex, the applicable method is: establish a sharper single “peak” hero moment; explicitly reject generic SaaS-card layouts and decorative accent repetition; define a constrained component/state system; test visual hierarchy at actual rendered scale; and make every transition advance the story. Repository material is treated as methodology only: no repository code, branding, creative output, or scripts will be copied or executed.

Reference: [Auteur repository README and skill overview](https://github.com/agiwhitelist/auteur).

## Build Register Selected for Vibex

This redesign is a single public portfolio surface, so Auteur’s **build register** is the appropriate route: a conventional page executed with one signature element, a committed visual system, real typography, and disciplined motion rather than a forced cinematic scroll narrative.

Before implementation, the method requires a written commit-sheet, including one signature moment, color commitment with a measurable lightness target, a reasoned type pairing, a concrete grid break, a maximum of three motion families, a two-order category-reflex check, and two deliberately avoided Auteur house tells. The build must use semantic content before visual styling; motion appears only after layout, typography, and color are established. Verification will include a production build, cross-viewport screenshots, a visual reference comparison, and accessibility checks.
